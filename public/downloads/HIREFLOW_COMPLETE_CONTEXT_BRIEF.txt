1. Executive Summary & Product Mission
--------------------------------------------------------------------------------

HireFlow is a privacy-first, client-side career intelligence platform, deterministic Applicant Tracking System (ATS) evaluation engine, and dual-sided talent management ecosystem.


[ The Mission ]

To replace unreliable "AI buzzword wrappers" and opaque ATS screening algorithms with verifiable, deterministic, evidence-grounded career intelligence. 

HireFlow bridges the gap between candidates (who need to know exactly how they are evaluated and what real technical skills they must build) and enterprises / hiring managers (who require verified candidate proof, calibrated competencies, and structured interview loops).


[ Foundational Differentiators ]

- 100% Client-Side Privacy: Zero candidate data exfiltration. Resume parsing (pdfjs-dist, mammoth), matching algorithms, and document generation (docx) execute entirely inside the candidate's browser sandbox.
- Zero-Hallucination Standard (The Truth Gate): Unlike standard generative AI resume builders that fabricate metrics, invent previous employers, or stuff synthetic buzzwords, HireFlow enforces mathematical proof. Any metric, date, or technology presented in a tailored output must originate from the candidate's verified fact ledger.
- Dual-Sided Calibration: The platform powers both sides of the hiring equation. Candidates use the Decision Suite to inspect ATS scores and close skill gaps; Business HR Managers (BHRs) and interviewers use the Enterprise Portal to calibrate job descriptions, inspect candidate evidence scorecards, and run structured interview loops.

2. The Core Problem Landscape & Industry Need
--------------------------------------------------------------------------------


[ 2.1 The Candidate Dilemma ]

1. The ATS Black Box: Over 75% of resumes submitted online are rejected before reaching a human recruiter. Traditional ATS tools reject candidates for trivial formatting issues, parsing anomalies, or slight vocabulary mismatches (e.g., "Postgres" vs "PostgreSQL"). Candidates have had zero transparency into why they failed.
2. The Generative AI "Hallucination Trap": Current AI resume tools promise quick results by using open-ended LLMs to rewrite resumes. These tools routinely fabricate metrics ("increased revenue by 42%"), hallucinate software libraries the candidate never touched, and mangle career timelines. When probed by an engineering interviewer, these fabricated claims collapse, permanently damaging the candidate's reputation.
3. The "What Do I Build?" Void: When candidates identify skill gaps (e.g., missing distributed caching or Kafka experience), they turn to simplistic "todo list" tutorial projects that recruiters instantly dismiss. Candidates lack market-backed, production-grade architectural blueprints that prove Senior/Staff-level competency.
4. Credential Navigation Chaos: Students and career switchers waste thousands of dollars on unverified bootcamps or commercial certificates that hold zero weight with enterprise screeners, while missing 100% free or heavily subsidized flagship credentials, hackathons, and open-source fellowships (e.g., GSoC, SIH, LFX, AWS/GCP student fee waivers).


[ 2.2 The Employer & Recruiter Dilemma ]

1. Resume Spam & Synthesized Fraud: Recruiters receive hundreds of resumes stuffed with keywords and AI-generated summaries, making it nearly impossible to identify authentic hands-on capability.
2. Uncalibrated Job Descriptions: Hiring teams publish conflicting JDs with impossible requirements (e.g., "10 years of experience in a 4-year-old framework"), repelling qualified candidates.
3. Subjective & Unstructured Interview Loops: Without standardized rubric checklists and calibrated evidence cards, hiring decisions devolve into subjective bias rather than technical capability.

4. Platform Modules & Feature Tour
--------------------------------------------------------------------------------


[ 4.1. ATS Resume Roaster & Evidence Evaluator (/tools/resume-checker) ]

- 4-Pillar Deterministic Evaluation:
  - Hard Skills Match (40% Weight): Evaluates exact keyword matches, recognized aliases, and transferable ontological relationships.
  - Writing Quality & Evidence (25% Weight): Checks for XYZ formula bullets (Accomplished [X] as measured by [Y] by doing [Z]), action verbs, fluff phrases, and passive voice.
  - Seniority & Role Fit (20% Weight): Analyzes leadership scope, architectural verbs, and years of experience alignment against role level.
  - ATS Format Safety (15% Weight): Checks for table nesting, two-column layouts, graphics, complex headers/footers, and non-standard bullet characters that break parsers.
- Harsh Truths & Actionable Fixes: Translates technical shortcomings into direct feedback (e.g., "You listed Kubernetes in your skills, but zero bullet points mention deploying, monitoring, or configuring a cluster").
- Verbatim Evidence Citations: Directly highlights the exact phrase in the candidate's resume that satisfied each requirement.


[ 4.2. Dual-Role Job Description Comparison Engine (/tools/jd-compare) ]

- Head-to-Head Architectural Breakdown: Evaluates candidate fit across two competing job postings simultaneously.
- Synchronized Metric Rings:
  - Overall Fit Score (0-100%)
  - Must-Have Skill Coverage
  - Callback Probability Index
  - Readiness Tier (Ready to Apply vs Needs Bridge Project)
- Venn Divergence Matrix: Categorizes requirements into:
  - Shared Core Skills: Foundational capabilities required by both companies.
  - Role A Exclusive: Specialized technologies required only by Role A.
  - Role B Exclusive: Specialized technologies required only by Role B.
- 3-Step Actionable Bridge Plan: Identifies the single high-leverage project or credential that closes the gap for both roles simultaneously.


[ 4.3. 7-Stage Zero-Hallucination Resume Tailoring Engine (/tools/tailor) ]

A linear, deterministic tailoring pipeline that adapts resumes to target JDs without fabricating facts:
- Stage A (Select/Upload): Ingests PDF, DOCX, or TXT into an immutable Candidate Fact Ledger.
- Stage B (Add Target JD): Ingests raw job description, cleans boilerplate, and extracts structured requirements.
- Stage C (Analyze Requirements): Categorizes requirements into Mandatory, Preferred, Domain Acronyms, and Core Tasks.
- Stage D (Review Evidence & Truth Mapping): Interactive matrix classifying matches into DIRECT, TRANSFERABLE, PARTIAL, MISSING, and UNCERTAIN.
- Stage E (Strategy & Ordering): Dynamic career-stage playbook sequencing (Student/Fresher vs Mid-Level vs Senior).
- Stage F (Split Workspace & Live Preview): Side-by-side editing pane and live rendered paper preview (Letter/A4) with live keyword highlights.
- Stage G (Validate & Export): Truth Gate audit, height/overflow sentinel check, and multi-format export parity (Word .docx, Print .pdf, Plain Text .txt).

- Greedy Set-Cover Algorithm: Computes the minimal set of production projects needed to cover 100% of a candidate's target JD skill gaps in the fewest estimated hours.
- Deep Technical Specifications: Every brief contains Problem Statement, Real-World Use Cases, Technical Depth Rationale, Recruiter Shortlist Signal, ASCII Architecture & Data Flow, Scale Targets, Screener Verification Rubric, and an ATS-optimized Resume Portfolio Bullet.

5. System Architecture & The 10 Prime Directives
--------------------------------------------------------------------------------

HireFlow is engineered according to 10 Non-Negotiable Prime Directives:

`
+-----------------------------------------------------------------------------------+
|                        THE 10 PRIME ARCHITECTURAL DIRECTIVES                      |
+-----------------------------------------------------------------------------------+
| P1  | QUALITY FLOOR        | score(output) >= score(source) on every metric       |
| P2  | ZERO SILENT LOSS     | Every source fact is shown or safely archived        |
| P3  | NEVER FABRICATE      | The engine asks questions; it never invents facts    |
| P4  | TAILOR HARD          | Reorder, relabel, and mirror verified JD terminology |
| P5  | ONE LAYOUT TREE      | Preview, PDF, DOCX, and TXT render the same AST      |
| P6  | DETERMINISTIC FIRST  | Parsing, matching, and scoring are pure code         |
| P7  | NON-DESTRUCTIVE      | Base resume is an immutable fact ledger              |
| P8  | SAFE BY CONSTRUCTION | Every UI button is mathematically safe to click      |
| P9  | HONEST SCORES        | Single authoritative definition per metric           |
| P10 | READABLE UI          | WCAG AA contrast compliance across light and dark    |
+-----------------------------------------------------------------------------------+
`


[ Detailed Breakdown of Key Directives: ]

1. P1: Quality Floor: The tailored resume must never score lower than the original resume on any dimension. If a proposed rewrite degrades clarity, the engine automatically falls back to the original phrasing.
2. P2: Zero Silent Loss: Any detail present in the user's uploaded resume (education, achievements, certifications, leadership) must appear in the final output or be placed into a user-visible "Archived" drawer.
3. P3: Never Fabricate (Ask, Don't Answer): If a target job description requires a skill or metric not present in the candidate's resume, the engine never manufactures an answer. Instead, it generates an interactive question with an empty input field.
4. P5: One Layout Tree, Many Renderers: Preview, PDF export, Word DOCX export, and Plain Text renderers do not make layout or content decisions. They are pure translators of a single immutable layout tree.
5. P7: Non-Destructive Fact Ledger: When a candidate uploads a resume, it is parsed into an immutable CandidateFactLedger. Tailored resumes are merely ordered operations (Variants) projected over the ledger.

7. Mathematical & Algorithmic Framework
--------------------------------------------------------------------------------


[ 7.1 ATS Fit Scoring Formulation ]

The Composite ATS Evidence Score $S_{total}$ is calculated as:

$$S_{total} = w_h \cdot S_{hard} + w_q \cdot S_{quality} + w_s \cdot S_{seniority} + w_f \cdot S_{format}$$

Where:
- $w_h = 0.40$ (Hard Skills Match)
- $w_q = 0.25$ (Writing Quality & Evidence)
- $w_s = 0.20$ (Seniority & Scope Alignment)
- $w_f = 0.15$ (Format & Structural Safety)


* Hard Skills Score ($S_{hard}$)

$$S_{hard} = \frac{\sum_{i \in Req} \omega_i \cdot \delta(i)}{\sum_{i \in Req} \omega_i} \times 100$$

Where $\omega_i$ is the requirement weight:
- $\omega_i = 3.0$ for Mandatory Requirements
- $\omega_i = 1.5$ for Preferred Qualifications
- $\omega_i = 1.0$ for Mentioned Skills

And $\delta(i)$ is the match multiplier:
- $\delta(i) = 1.0$ for Direct Match (exact term or canonical alias)
- $\delta(i) = 0.7$ for Transferable Match (ontological sibling/parent)
- $\delta(i) = 0.4$ for Partial Match (lesser experience or related ecosystem)
- $\delta(i) = 0.0$ for Missing Evidence


[ 7.2 Greedy Set-Cover Project Bundler ]

Given a set of missing candidate skill gaps $U = \{g_1, g_2, \dots, g_n\}$ and a library of $m$ project briefs $P = \{p_1, p_2, \dots, p_m\}$ where each project $p_j$ covers skills $C(p_j) \subseteq U$ and has estimated build hours $H(p_j)$:

The algorithm iteratively selects the project $p^*$ that maximizes coverage efficiency:

$$p^* = \arg\max_{p \in P} \frac{|C(p) \cap U_{remaining}|^{\alpha}}{H(p)}$$

Where $\alpha \ge 1.0$ is the difficulty weighting factor. The loop terminates when $U_{remaining} = \emptyset$ or when a maximum of 4 projects is reached.

11. Verification, Testing Strategy & Security Audits
--------------------------------------------------------------------------------


[ 11.1 Test Invariants ]

- Schema & Taxonomy Invariants: Verifies that all 83 project briefs and 102 credentials conform strictly to their respective Zod/TypeScript schemas.
- Truth Gate Invariant: Rejects any candidate document where a metric or tool appears in a tailored bullet point without originating from the candidate's fact ledger.
- Multi-Renderer Parity: Ensures that content rendered in the HTML canvas preview matches byte-for-byte in the .docx Word export and .pdf print export.
- Accessibility & Contrast: All UI text elements are audited against WCAG AA color contrast standards (minimum 4.5:1 for normal text, 3:1 for large text).


[ 11.2 Security & Privacy Strategy ]

- Zero Remote Storage of PII: Resumes and candidate notes remain inside browser memory or localStorage.
- Zero API Key Leakage: No hardcoded external secrets. Automated CI secret scanner (scripts/security/scan-secrets.mjs) executes before builds.
- Dependency Audit: Regular automated audit (scripts/security/audit-deps.mjs) ensuring zero high or critical CVE vulnerabilities.

12. Local Setup, Execution & Deployment Guide
--------------------------------------------------------------------------------


[ Prerequisites ]

- Node.js 18.0.0 or higher
- npm 9.0.0 or higher (or pnpm)


[ Installation ]

`bash

================================================================================
Clone the repository
================================================================================
git clone https://github.com/Mohit-Rocky-25/hireflow.git
cd hireflow


================================================================================
Install exact dependencies
================================================================================
npm install
`


[ Running Locally ]

`bash

================================================================================
Launch Vite development server
================================================================================
npm run dev
`
The application will be live at http://localhost:5173.


[ Running Verification & Tests ]

`bash

================================================================================
Run complete Vitest suite
================================================================================
npm run test


================================================================================
Run TypeScript typecheck
================================================================================
npm run lint


================================================================================
Run security checks
================================================================================
npm run security:check
`


[ Production Build ]

`bash

================================================================================
Compile and package for production
================================================================================
npm run build


================================================================================
Preview production build locally
================================================================================
npm run preview
``
