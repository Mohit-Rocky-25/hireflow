PROBLEM STATEMENT
----------------------------------------------------------------------
Generic static UI interfaces deliver lower user engagement, subpar conversion rates, and elevated bounce rates compared to dynamic personalized digital experiences. However, traditional batch-recomputed recommendation pipelines suffer from multi-hour stale recommendations, inability to capture intra-session user intent shifts, and crippling cold-start latency for newly launched items. This project builds a production-grade real-time personalization and contextual bandit recommendation engine in Python. The system ingests user interaction event streams over Apache Kafka, aggregates real-time session feature vectors in Redis with sub-millisecond retrieval, trains LinUCB and Thompson Sampling contextual bandit models with Scikit-learn, and serves personalized ranking recommendations via FastAPI with sub-18ms p95 latency.

ARCHITECTURE & DATA FLOW
----------------------------------------------------------------------
Components:
- Kafka Clickstream Ingestion & Event Processing Worker (Tools: Python, Kafka): Consumes user interaction events (views, clicks, purchases) from Kafka topics and normalizes event payloads
- Redis Real-Time Session Feature Store & Aggregator (Tools: Python, Redis): Updates rolling category interaction counters and maintains low-latency user session feature vectors in Redis
- Contextual Bandit & Thompson Sampling Model Engine (Tools: Python, Scikit-learn): Implements LinUCB and Thompson Sampling algorithms balancing exploration and exploitation across candidate items
- FastAPI Low-Latency Recommendation Inference Service (Tools: Python, FastAPI): Accepts user recommendation requests, fetches session features from Redis, scores candidates, and returns ranked IDs
- Celery Batch Retraining & Offline Evaluation Pipeline (Tools: Python, Celery, Scikit-learn): Executes background batch retraining of bandit inverse covariance matrices and logs cumulative regret metrics
- Recommendation Throughput & Latency Benchmark Harness (Tools: Python, FastAPI): Simulates 500 concurrent recommendation requests per second and profiles Redis lookup and scoring latencies
- Personalization Architecture Guide & Feature Store Schema (Tools: Python, Redis): Documents feature vector TTL strategies, cold-start fallback heuristics, and contextual bandit math proofs

Data Flow:
A user clicks an item on the client UI; an engagement event publishes to the Kafka 'user-clicks' topic; the Kafka worker consumes the event and updates category view counters in Redis with a 30-minute sliding TTL; when the client requests personalized recommendations, FastAPI receives the user ID, executes an MGET against Redis to retrieve active session features in < 2ms, feeds the features into the LinUCB bandit scoring model, computes confidence bound scores for candidate items, filters previously viewed items, and returns top-K ranked item IDs; Celery periodically pulls historical conversion logs to retrain offline models.

Enforcement Mechanism:
Linear algebra ridge regression matrix inversion updates with L2 regularization preventing numerical divergence; bounded Redis memory TTLs.
