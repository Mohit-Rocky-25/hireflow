PROBLEM STATEMENT
----------------------------------------
Fixed-horizon frequentist A/B testing requires accumulating a predetermined sample size before evaluating outcomes, prolonging exposure to suboptimal variants and encouraging premature stopping errors (peeking). When engineering teams inspect p-values continuously without formal alpha-spending adjustments, false positive discovery rates escalate significantly. A Bayesian experimentation engine addresses this by maintaining continuous posterior probability distributions over conversion rates, calculating the exact probability that a candidate variant outperforms the baseline and quantifying the expected metric loss of selecting that variant, enabling automated early stopping decisions while mathematically bounding decision risk.

USE CASES IN THE REAL WORLD
----------------------------------------
Digital platforms utilize sequential experimentation engines to evaluate user interface variants, checkout funnels, and algorithmic ranking models. Neutral architectural reference points include open-source and commercial experimentation platforms such as Optimizely, Statsig, and GrowthBook.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
Preventing False Positive Inflation Under Continuous Inspection: While Bayesian updating is logically coherent under sequential data arrivals, naive early stopping upon reaching uncalibrated tail probabilities (P(B > A) > 0.95) during low-sample cold starts (N < 200) causes severe discovery bias due to early random walk fluctuations. The engine must enforce minimum statistical sample boundaries (N_min) and evaluate Expected Loss thresholds (loss < ε) rather than relying purely on posterior tail probabilities. Furthermore, computing continuous updates across concurrent event streams requires vectorized closed-form conjugate updating rather than expensive Monte Carlo sampling.

ARCHITECTURE & DATA FLOW
----------------------------------------
1. Ingestion: Client conversion events arrive via FastAPI POST endpoints and append to a write-optimized PostgreSQL log with atomic sequence counters.
2. Inference Engine: An analytical statistical worker evaluates Beta-Binomial conjugate posteriors Beta(α0 + k, β0 + n - k) using exact numerical quadrature via SciPy for 2-arm variants.
3. Decision Logic: For active experiments where sample size exceeds N_min, the engine evaluates Expected Loss: L(B) = ∫ max(θA - θB, 0) p(θA, θB) dθ. If P(B > A) > threshold and Expected Loss < ε, state transitions automatically to STOPPED_WINNER; if Expected Loss for both arms is < ε, state transitions to STOPPED_INCONCLUSIVE.
4. Reporting: REST endpoints expose experiment states, credible intervals (95% HDI), posterior densities, and decision histories.
