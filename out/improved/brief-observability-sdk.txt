PROBLEM STATEMENT
----------------------------------------
Adding observability to production applications requires manual instrumentation of every function, HTTP call, and database query. Build a zero-code auto-instrumentation SDK that transparently wraps common libraries (Express, Axios, PostgreSQL, Redis) with tracing, metrics, and logging.

USE CASES IN THE REAL WORLD
----------------------------------------
Datadog's APM agent, New Relic's agent, and OpenTelemetry auto-instrumentation libraries all solve this. Any company with internal services wanting to add observability without rewriting application code needs this. Platform teams use instrumentation SDKs to enforce consistent telemetry across all services.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
SDK design requires understanding Node.js module system patching (monkey-patching), async context propagation, and the OpenTelemetry API/SDK separation. Building an SDK that doesn't require application code changes demonstrates advanced understanding of runtime environments and observability engineering.

ARCHITECTURE & DATA FLOW
----------------------------------------
TypeScript library using Node.js module patching to wrap Express.js routes, Axios HTTP calls, pg (PostgreSQL), and Redis client with OpenTelemetry spans automatically. AsyncLocalStorage for context propagation across async boundaries. Prometheus counter/histogram middleware injected via app factory. Zero-configuration setup with sensible defaults.
