Naive serverless deployments experience crippling cold-start latency spikes, duplicate transaction executions from unhandled SQS retries, and silent message loss when downstream APIs fail. ARCHITECTURE & DATA FLOW
----------------------------------------------------------------------
Components:
- API Gateway Order Submission Endpoint & Request Validator (Tools: Python, API Gateway, LocalStack): Terminates client HTTP POST orders, validates payload schemas, and proxies messages directly to Amazon SQS
- Amazon SQS Order Buffer & Dead Letter Queue (DLQ) Manager (Tools: Python, SQS, LocalStack): Buffers order messages, manages visibility timeouts, and routes persistently failing messages to a dead letter queue
- AWS Lambda Idempotent Order Processing & Fulfillment Worker (Tools: Python, AWS Lambda, LocalStack): Consumes batches of SQS messages, verifies idempotency keys, and triggers order fulfillment status changes
- Amazon DynamoDB Order State Table & Conditional Writer (Tools: Python, DynamoDB, LocalStack): Stores order records with composite primary keys (CustomerID, OrderID) and enforces atomic conditional updates
- Serverless Order Throughput & Concurrency Benchmark Harness (Tools: Python, LocalStack): Simulates 1,000 concurrent order submissions and measures end-to-end processing latencies and DLQ routing
- Serverless Architecture Guide & LocalStack Infrastructure Manual (Tools: Python, LocalStack): Documents serverless deployment automation, IAM least-privilege policies, and DynamoDB single-table design

Data Flow:
A client sends an order JSON via HTTP POST to API Gateway; API Gateway validates the schema and enqueues the message directly into Amazon SQS, returning an order receipt ID to the client in < 25ms; SQS triggers the Order Processing Lambda function in batches of 10 messages; the Lambda function extracts the idempotency key and executes a conditional PutItem on DynamoDB (`attribute_not_exists(order_id)`); if the order already exists, it ignores duplicate processing; if new, it writes the order with status 'CONFIRMED' and updates inventory; if an unhandled error occurs, SQS retries the message 3 times before moving the payload to the DLQ; clients query order status via a secondary API Gateway endpoint.

Enforcement Mechanism:
DynamoDB conditional expressions (`attribute_not_exists(order_id)`) preventing duplicate transactions; SQS maxReceiveCount=3 bounding retries.
