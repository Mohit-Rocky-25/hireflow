PROBLEM STATEMENT
----------------------------------------
Traditional always-on servers are expensive for variable-traffic applications. Build a fully serverless event-driven backend that scales to zero when idle and handles traffic spikes without pre-provisioning, using AWS Lambda, API Gateway, DynamoDB, and SQS for asynchronous processing.

USE CASES IN THE REAL WORLD
----------------------------------------
Startups and indie developers use serverless to minimize infrastructure costs. Any API with variable traffic (seasonal e-commerce, event-based applications, webhook processors) benefits from serverless economics. AWS Lambda powers backends for companies of all sizes.

WHY THIS IS HARD (COMPETENCY REDUCER)

Serverless architecture requires understanding cold start optimization, DynamoDB access patterns, Lambda concurrency limits, SQS retry semantics, and IAM least-privilege configuration — a different mental model from traditional server development. Building serverless demonstrates cloud-native engineering.
