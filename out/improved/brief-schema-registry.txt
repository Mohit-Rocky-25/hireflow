PROBLEM STATEMENT
----------------------------------------
Microservices publishing and consuming Kafka events break silently when producers change event schemas without notifying consumers. Build a centralized schema registry that enforces backward-compatible schema evolution, generates type-safe consumer contracts, and validates events at runtime.

ARCHITECTURE & DATA FLOW
----------------------------------------
FastAPI schema registry storing versioned Avro/JSON schemas in PostgreSQL. Compatibility checker enforcing BACKWARD/FORWARD/FULL compatibility rules on schema updates. Kafka producer client library validating events against registered schema before publish. Consumer library decoding events with schema version from message header.
