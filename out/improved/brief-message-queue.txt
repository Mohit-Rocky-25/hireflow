PROBLEM STATEMENT
----------------------------------------
Building a reliable message queue from scratch — not using RabbitMQ or Kafka — requires solving fundamental distributed systems problems: message persistence, consumer group coordination, delivery acknowledgement, and dead-letter handling. Implement a simple but production-correct message queue.

USE CASES IN THE REAL WORLD
----------------------------------------
Understanding queue internals enables you to configure Kafka partitions correctly, debug RabbitMQ delivery guarantees, and explain message ordering to interviewers. Any asynchronous workflow (order processing, email delivery, notification dispatch) relies on these semantics.

ARCHITECTURE & DATA FLOW
----------------------------------------
Go TCP server with append-only log segments for message persistence. Consumer groups with offset tracking in metadata store. Acknowledgement window with redelivery on timeout. Dead-letter queue for repeatedly failed messages. Producer with configurable durability (sync/async). HTTP management API.
