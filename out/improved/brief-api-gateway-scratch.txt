PROBLEM STATEMENT
----------------------------------------
Microservice architectures require centralized ingress points to manage cross-cutting networking concerns—such as request authentication, rate limiting, and dynamic traffic routing—without duplicating logic across individual backend services. In horizontally-scaled environments, an ingress gateway must maintain low proxy overhead, support hot-reloading of routing rules without connection drops or race conditions, balance traffic across upstream replicas using health checks, and execute extensible middleware plugins without introducing unbounded memory allocations or TCP socket leaks.

USE CASES IN THE REAL WORLD
----------------------------------------
Cloud platforms and container orchestrators rely on edge gateways to route external traffic to internal microservices. Neutral architectural reference points include open-source reverse proxies and gateways such as Envoy, Apache APISIX, and Traefik.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
TCP Connection Pooling & File Descriptor Leaks: Default HTTP transports restrict concurrent connections per upstream host (MaxIdleConnsPerHost = 2), causing rapid socket churn and TIME_WAIT saturation under high concurrency. The proxy must implement a tuned custom http.Transport with aggressive connection reuse and leak-free response body consumption. Furthermore, hot-reloading routing configurations without downtime requires atomic pointer swaps (atomic.Pointer[RouteTable]) to prevent Go data races during concurrent read operations.

ARCHITECTURE & DATA FLOW
----------------------------------------
1. Ingress Listener: Go HTTP server accepts incoming client TCP connections, binds request contexts with timeouts, and forwards requests to the core gateway handler.
2. Route Matching: Incoming request paths and HTTP methods match against an in-memory route table accessed via an atomic pointer.
3. Plugin Pipeline: Middleware plugins execute sequentially: Authentication (header validation) -> Rate Limiter (token bucket algorithm) -> Header/Path Transformation.
4. Reverse Proxying & Load Balancing: Matched requests route to an upstream pool evaluated via Weighted Round-Robin. Traffic forwards via net/http/httputil.ReverseProxy backed by a tuned http.Transport (MaxIdleConns: 1000, MaxIdleConnsPerHost: 200).
5. Background Health Checker: A dedicated goroutine polls upstream /healthz endpoints at 1s intervals. Failed nodes are dynamically evicted from the active pool without gateway restarts.
6. Admin API: An isolated administrative HTTP server accepts route mutations and atomically swaps the active routing table pointer.
