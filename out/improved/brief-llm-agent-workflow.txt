PROBLEM STATEMENT
----------------------------------------------------------------------
Uncontrolled LLM agents deployed with naive prompt loops suffer from infinite execution cycles, hallucinatory tool parameterization, and total loss of state upon downstream API failures. Relying on opaque framework abstractions obscures tool invocation errors and prevents deterministic workflow resumption. This project builds an autonomous agent orchestration engine in Python. The engine implements a stateful ReAct (Reasoning and Acting) loop, enforces structured tool calling schemas via Pydantic, tracks execution graphs with cycle detection, persists step-by-step workflow state in Redis, and guarantees graceful fallback handling when external tools fail or timeout.

ARCHITECTURE & DATA FLOW
----------------------------------------------------------------------
Components:
- ReAct Reasoning & Planning Loop Controller (Tools: Python, LangChain): Orchestrates Thought-Action-Observation cycles, evaluates goal completion, and detects infinite plan loops
- Deterministic Tool Registry & Dispatch Gateway (Tools: Python, Pydantic): Registers tool plugins, validates input parameters against Pydantic schemas, and manages timeouts
- Redis State Checkpoint & Rollback Store (Tools: Python, Redis): Persists execution history, tool outputs, and variable contexts after every intermediate workflow step
- Exception Handling & Tool Fallback Manager (Tools: Python, FastAPI): Catches tool errors, injects explanatory feedback into agent context, and routes to alternate tools
- Agent Execution Graph & Trace API (Tools: FastAPI, Pydantic): Exposes real-time execution trace endpoints, step telemetry, and workflow cancellation hooks
- Task Completion & Chaos Failure Benchmark Suite (Tools: Python, Docker): Executes 100 benchmark multi-step goals with chaos tool failure injections, measuring completion metrics
- Agent Architecture Guide & Plugin Protocol Documentation (Tools: Docker): Documents tool registration interface, execution safety bounds, and state checkpoint schema

Data Flow:
A user request enters the FastAPI execution gateway; the planning controller prompts the LLM to generate an initial Thought and Action; the tool dispatcher validates parameter arguments against the tool's Pydantic schema; if valid, the tool executes within its timeout budget; the Observation result writes to the Redis checkpoint store; if the tool fails, the fallback manager injects error details into the prompt context for replanning; the controller iterates through subsequent Thought-Action-Observation turns until a final answer synthesizes or the step budget exhausts.

Enforcement Mechanism:
Maximum step budget (default 10 iterations) terminating runaway loops; Pydantic argument parsing rejecting malformed tool parameters before execution.
