PROBLEM STATEMENT
----------------------------------------
GDPR, India's DPDP Act, and healthcare regulations prohibit sharing raw data for ML training. Federated Learning enables training models on decentralized data without sharing raw records. Build a federated learning system where multiple clients train local models and securely aggregate updates on a central server.

USE CASES IN THE REAL WORLD
----------------------------------------
Healthcare federated learning (hospitals training diagnostic models without sharing patient records), keyboard prediction on mobile devices (distributed systems platforms Gboard), fraud detection across bank branches, and IoT device anomaly detection — all require learning from distributed private data.

WHY THIS IS HARD (COMPETENCY REDUCER)

Understanding gradient aggregation, differential privacy noise addition, communication efficiency (gradient compression), and federated evaluation requires both distributed systems and ML expertise — a rare and highly valued combination.

ARCHITECTURE & DATA FLOW
----------------------------------------
FedAvg (Federated Averaging) algorithm: central server distributes model weights to N clients, each client trains on local private data for K epochs, clients send gradient updates to server, server applies differential privacy noise (Gaussian mechanism) before aggregation. PySyft or custom implementation with gRPC communication.
