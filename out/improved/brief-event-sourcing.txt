PROBLEM STATEMENT
----------------------------------------
Traditional mutable database applications lose the history of how data changed, making debugging, auditing, and time-travel queries impossible. Build an Event Sourcing framework where all state changes are stored as immutable events, and current state is derived by replaying the event log.

USE CASES IN THE REAL WORLD
----------------------------------------
Financial audit trails (every transaction history preserved), legal compliance (immutable evidence of who changed what when), version control systems, and domain-driven design applications. Martin Fowler's event sourcing pattern is used at top tech platforms, top tech platforms, and any application requiring complete audit history.

ARCHITECTURE & DATA FLOW
----------------------------------------
Event store in PostgreSQL with append-only event table. Aggregate loading via event replay from store. Projections computing read models from event streams asynchronously. Kafka for event distribution to multiple projection workers. Snapshot mechanism for performance on long event streams. Time-travel query API for historical state retrieval.
