PROBLEM STATEMENT
----------------------------------------------------------------------
Software-as-a-service telemetry systems collect high-volume behavioral event streams from web and mobile applications, but executing ad-hoc funnel conversions and cohort retention aggregations on row-oriented transactional databases creates severe disk I/O bottlenecks and query timeouts. Relational databases store records contiguously on disk, forcing full-row deserialization even when queries touch only a few analytical columns. A multi-tenant analytics platform overcomes this limitation by streaming telemetry through an ingestion buffer into a columnar storage engine, compressing column payloads with dictionary and delta encodings and leveraging partitioned sparse primary keys to achieve sub-second analytical aggregations across multi-tenant datasets.

USE CASES IN THE REAL WORLD

- Weekly and monthly retention cohort calculation for subscription software products

- Structuring sparse primary keys to balance tenant-level isolation with temporal range scan performance

- Formulating vectorized SQL queries using windowFunnel and retention functions within bounded server memory limits

ARCHITECTURE & DATA FLOW
----------------------------------------------------------------------
Components:
- Beacon Ingestion Receiver (Tools: TypeScript, Node.js): Validates incoming telemetry payloads against strict schemas and publishes to partitioned Kafka topics
- Buffer Ingestion Pipeline (Tools: Kafka, TypeScript, Node.js): Consumes stream data pipelines and flushes micro-batches into ClickHouse columnar databases
- Columnar Analytical Storage (Tools: ClickHouse, SQL): Stores event rows in a ReplacingMergeTree table sorted by tenant_id, event_name, and timestamp with ZSTD compression
- Multi-Tenant Query Service (Tools: TypeScript, Node.js, SQL): Exposes parameterized analytical APIs executing windowFunnel and retention cohort SQL aggregations
- Containerized Test Environment (Tools: Docker): Orchestrates isolated local execution of ClickHouse, Kafka broker, and Node.js microservices

Data Flow:
Client HTTP beacons are ingested by Node.js; validated events are buffered in Kafka topics partitioned by tenant; consumer groups aggregate records into micro-batches of several thousand rows; batches are inserted into ClickHouse ReplacingMergeTree tables; analytical dashboard queries invoke specialized ClickHouse SQL functions to compute aggregate funnels and cohorts.

Enforcement Mechanism:
Ingestion service enforces batch flush boundaries (either batch threshold or maximum time interval) to prevent part explosion; ClickHouse table schema enforces primary index sorting on tenant_id and timestamp.
