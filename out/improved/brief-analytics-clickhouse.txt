PROBLEM STATEMENT
----------------------------------------
SaaS telemetry platforms process millions of interaction events daily from web and mobile clients, but querying aggregate funnel conversions, retention cohorts, and time-series metrics on traditional row-oriented OLTP databases results in excessive query latency and timeouts once tables exceed tens of millions of rows. Analytical systems require columnar storage, data compression, and partitioned indexing to scan billions of values per second. This project builds a multi-tenant telemetry ingestion and analytical engine that streams event beacons through Kafka into a partitioned ClickHouse cluster, maintaining sub-second aggregation latencies across multi-million row datasets.

USE CASES IN THE REAL WORLD
----------------------------------------
Product analytics platforms ingest high-throughput user clickstreams to generate real-time behavioral metrics. Neutral architectural reference points include open-source and commercial product analytics systems such as PostHog, Mixpanel, and Amplitude.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
Preventing Part Explosion: ClickHouse creates immutable physical directory parts for every write transaction. Ingesting high-frequency single records directly triggers the 'Too many parts in all data in table' exception. The ingestion pipeline must enforce batch buffering (minimum 10,000 events or 5-second flushes) before persisting to disk.

RECRUITER SHORTLIST SIGNAL
----------------------------------------
Demonstrates mastery of the OLTP vs. OLAP boundary, columnar database internals (sparse primary keys, column encoding, merge policies), and high-throughput streaming architecture. Directly maps to Data Platform Engineer, Analytics Engineer, and Backend Data Infrastructure roles.

ARCHITECTURE & DATA FLOW
----------------------------------------
Node.js/TypeScript HTTP receiver validates incoming JSON beacons against strict schemas and publishes to partitioned Kafka topics keyed by tenant_id. ClickHouse consumes from Kafka via Kafka Engine and buffers columnar batches of 10,000+ records into a ReplacingMergeTree table partitioned by toDate(timestamp) with ZSTD compression. Analytical query layer exposes REST endpoints for funnel conversions, retention cohorts, and time-series metrics.
