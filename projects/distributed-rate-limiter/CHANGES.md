# Changes & Audit Log: Distributed Rate Limiter & Token Bucket Gateway

## Findings & Decisions Table

| Finding | Severity | What the Original Said | What Was Changed | Why |
| :--- | :--- | :--- | :--- | :--- |
| **Concurrency Mechanism Contradiction** | Blocker | Stated both "atomic Redis Lua scripts" and "Uses Redis WATCH/MULTI/EXEC for optimistic concurrency". | Standardized exclusively on atomic Redis Lua scripts (`EVALSHA`) and deprecated `WATCH`/`MULTI`/`EXEC`. | `WATCH`/`MULTI`/`EXEC` triggers extreme abort rates and CPU retry storms under 25,000 RPS concurrency, whereas Lua guarantees linearizable atomicity in $O(1)$. |
| **Unnamed Domain Entity & Schema** | Blocker | Had no concrete domain entity, fields, data types, or business validation rules. | Defined `RateLimitPolicy` entity with 8 typed fields (`policy_id`, `tenant_id`, `route_pattern`, `capacity`, `refill_rate`, `cost_per_req`, `fail_mode`, `created_at_epoch_ms`). | Provides an unambiguous, testable domain contract required for multi-tenant quota enforcement. |
| **Vague Metrics & Scale Targets** | Major | "Sustain 25,000 req/sec across 4 worker nodes with p99 latency overhead < 3.5ms and 99.99% enforcement accuracy." | Structured all metrics into 3 parts (value, test condition, measurement method) using automated k6 scripts and Go benchmarks. | Enforces Hard Rule 4 to eliminate vague performance claims with reproducible test conditions. |
| **Untestable Rubric Items** | Major | 5 high-level bullet points without concrete verification commands, thresholds, or weight allocations. | Created 7 structured rubric items with exact terminal commands, pass thresholds, evidence artifact paths, and weights summing to 100%. | Enables any screener to independently verify 100% machine-verifiable criteria in under 5 minutes. |
| **Missing Hour Allocation Breakdown** | Major | Stated estimated time of 20 hours without milestone partitioning. | Budgeted hours across 5 milestones (M1: 4h, M2: 5h, M3: 4h, M4: 3h, M5: 4h) totaling exactly 20 hours. | Fulfills Hard Rule 3 requiring milestone budgets to equal the estimated time within 10%. |
| **Missing Failure Mode & Resilience** | Major | Unstated behavior when Redis partitions, crashes, or times out. | Specified a configurable `Fail-Open` / `Fail-Closed` circuit breaker with a 10ms timeout and `X-RateLimit-Degraded` header. | Mitigates gateway cascade failures during backend cache outages in mission-critical ingress tiers. |
| **Undefined gRPC Scope Boundary** | Minor | Mentioned "Supports gRPC streaming and HTTP middleware headers". | Scoped to gRPC unary interceptors with standard `ResourceExhausted` code mapping, moving streaming to stretch. | Fits comfortably inside the 20-hour budget while fully validating the gRPC stack requirement. |
