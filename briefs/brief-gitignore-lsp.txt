PROBLEM STATEMENT
----------------------------------------
Code editors provide features like autocomplete, go-to-definition, and syntax highlighting through a protocol (LSP) that any language can implement. Build an LSP server for a custom DSL or configuration language, enabling VS Code to provide rich editing features: syntax validation, hover documentation, and completions.

USE CASES IN THE REAL WORLD
----------------------------------------
Any custom DSL or configuration language (Terraform HCL, Kubernetes YAML validation, GitHub Actions workflow validation) benefits from an LSP server. Companies with internal DSLs improve developer experience dramatically with LSP support. JetBrains, VS Code, and Neovim all support LSP.

ARCHITECTURE & DATA FLOW
----------------------------------------
TypeScript LSP server communicating via JSON-RPC over stdio. Document synchronization (open, change, close events). Incremental parsing maintaining AST for each open document. Completion providers using document symbols and schema definitions. Hover documentation from inline comments. Diagnostic publisher checking schema validation on every change.
