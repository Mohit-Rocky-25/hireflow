======================================================================

Tech Stack: Go, Kubernetes, Istio, Prometheus, GitHub Actions

PROBLEM STATEMENT
----------------------------------------
Deploying new code to 100% of users simultaneously risks massive user impact if the new version has bugs. Build a canary deployment controller that gradually shifts traffic from old to new service version, monitors error rates and latency, and automatically rolls back if SLO thresholds are violated.

USE CASES IN THE REAL WORLD
----------------------------------------
Progressive delivery is the gold standard at FAANG companies. Netflix, Amazon, and Spotify deploy hundreds of times per day using canary deployments. Any company with high-traffic production services uses traffic splitting to minimize deployment risk.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
Automated progressive delivery requires combining Kubernetes traffic management, Prometheus metrics analysis, and automated rollback decision logic — a sophisticated system that most engineers at small companies have never built. It proves you think about deployment safety at scale.

RECRUITER SHORTLIST SIGNAL
----------------------------------------
Progressive delivery knowledge (canaries, feature flags, blue-green) is required for senior DevOps and SRE roles. Engineers who can build the controller, not just use it, are principal-level infrastructure candidates. Directly applicable to platform teams at any company deploying at scale.

ARCHITECTURE & DATA FLOW
----------------------------------------
Kubernetes controller (reconciliation loop) managing a custom CRD (CanaryDeployment). Gradually shifts Istio VirtualService weights from stable (100%) to canary (0% → 10% → 25% → 50% → 100%). Prometheus metrics queried every 60 seconds: error rate, p99 latency. Automatic rollback if metrics exceed SLO thresholds.

SCALE & PERFORMANCE TARGETS
----------------------------------------
Automate traffic shift from 0% to 100% over 4 stages in < 1 hour with automated rollback triggered within 60 seconds of SLO violation detection.

4. Prometheus dashboard showing traffic split and per-version error rates during deployment
5. GitHub Actions integration triggering canary on every main branch merge
