PROBLEM STATEMENT
----------------------------------------
Engineering teams need to safely deploy features to specific user segments without full rollouts, enabling A/B testing and instant rollback. Build a feature flag management platform with percentage-based rollouts, user targeting rules, and real-time configuration updates without service restarts.

USE CASES IN THE REAL WORLD
----------------------------------------
LaunchDarkly and Split.io are billion-dollar companies built on this problem. Every engineering team deploying at scale uses feature flags. Swiggy, Zomato, and CRED run extensive A/B experiments to optimize UX and conversion rates. This is table-stakes infrastructure for any mature engineering organization.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
Feature flags require understanding of consistent hashing for user bucketing, real-time config propagation via WebSockets/SSE, and statistical significance for A/B test results — a combination of backend, distributed systems, and data concepts that few engineers have worked with end-to-end.

RECRUITER SHORTLIST SIGNAL
----------------------------------------

ARCHITECTURE & DATA FLOW
----------------------------------------
PostgreSQL flag definitions with user targeting rules (percentage rollout, user attribute targeting). Node.js API server with Redis cache for sub-millisecond flag evaluation. WebSocket/SSE push for real-time flag updates to client SDKs. React admin dashboard for flag management and experiment setup. Statistical significance calculator for A/B result evaluation.

SCALE & PERFORMANCE TARGETS
----------------------------------------
Evaluate 100,000 flag checks/sec with < 1ms latency via Redis, propagate flag changes to all connected clients within 500ms, and support 1,000 concurrent active experiments.

SKILLS COVERED
----------------------------------------
TypeScript, React, Node.js, PostgreSQL, Redis, REST APIs

SCREENER VERIFICATION RUBRIC
----------------------------------------
1. Percentage rollout: exactly N% of users consistently see flag=true across requests
2. User attribute targeting: flag enabled only for users in specific city/plan tier
3. Real-time update: toggle flag in UI and verify all connected clients update within 500ms
4. JavaScript SDK with < 1ms local flag evaluation from cached config
5. A/B result dashboard showing statistical significance and conversion rates per variant
