PROBLEM STATEMENT
----------------------------------------
Running user-submitted code safely requires strict sandboxing to prevent malicious code from compromising the host system. Build a secure remote code execution engine that sandboxes arbitrary user code in isolated containers with resource limits, network isolation, and process restrictions.

USE CASES IN THE REAL WORLD
----------------------------------------
Online judges (LeetCode, HackerRank, Codeforces), competitive programming platforms, coding interview tools, online IDEs (Repl.it, CodeSandbox), and educational coding environments. Any platform that lets users submit and execute code needs this infrastructure.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
Building a secure sandboxed execution engine requires understanding Linux security primitives (seccomp, namespaces, cgroups), container security, resource exhaustion prevention, and timing side channels. This is security engineering applied to execution infrastructure — a very specific and valuable skill.

RECRUITER SHORTLIST SIGNAL
----------------------------------------
Companies running online judges (HackerRank, LeetCode, CodeChef), coding interview platforms (Interviewing.io), and online IDEs need engineers who understand secure execution. Linux security, container isolation, and sandbox design are rare combinations that immediately impress security engineers.

ARCHITECTURE & DATA FLOW
----------------------------------------
Go orchestrator accepting code submissions. Docker container spawned per submission with strict resource limits (CPU time, memory, disk, network blocked). seccomp profile blocking dangerous system calls (exec, fork restrictions). gVisor or nsjail for additional sandboxing. Timeout enforcer killing containers exceeding time limit. Output capture and comparison.

SCALE & PERFORMANCE TARGETS
----------------------------------------
Execute 500 code submissions/min across 10 languages with < 2 second setup overhead, enforce memory and CPU limits within 5% accuracy, and guarantee zero host system compromise from malicious code.

SKILLS COVERED
----------------------------------------
Go, Docker, Linux, Security, System Design, Concurrency

SCREENER VERIFICATION RUBRIC
----------------------------------------
1. Fork bomb test: process creation limit blocks infinite fork() process exhaustion
2. Memory limit: process allocating beyond limit is OOM-killed within 100ms
3. Network isolation: container cannot make outbound network requests
4. Dangerous syscall block: exec(), socket() blocked by seccomp profile
5. Concurrent execution: 50 simultaneous submissions without cross-submission interference
