PROBLEM STATEMENT
----------------------------------------
Microservices need to react to database changes in other services without tight coupling. Traditional polling-based approaches create database load and introduce replication lag. Build a Change Data Capture pipeline using Debezium that streams database changes into Kafka and fans them out to multiple downstream consumers.

USE CASES IN THE REAL WORLD
----------------------------------------
Synchronizing search indexes with database changes (e-commerce product catalog search), replicating data from OLTP to OLAP databases, building event sourcing systems, and propagating changes across microservices in a decoupled manner.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
CDC is a fundamental data architecture pattern that eliminates polling, reduces database load, and enables event-driven architecture. Debezium specifically is the industry-standard CDC tool and is used at LinkedIn, top tech platforms, and most large engineering organizations. Understanding it is table stakes for senior data and backend engineers.

ARCHITECTURE & DATA FLOW
----------------------------------------
Debezium PostgreSQL connector reads WAL (Write-Ahead Log) and streams row-level changes to Kafka as structured JSON events. Separate Kafka consumers fan out to: Elasticsearch for search index sync, Redis for cache invalidation, and a notification service for downstream event triggers. Exactly-once semantics via transaction outbox pattern.
