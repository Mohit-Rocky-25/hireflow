PROJECT BRIEF — Real-Time Business Intelligence Dashboard with WebSocket Push
======================================================================

Domain    : Full-Stack Web
Difficulty: INTERMEDIATE
Est. Time : 20 hours
Tech Stack: React, TypeScript, Node.js, WebSockets, PostgreSQL, Redis

PROBLEM STATEMENT
----------------------------------------
Business stakeholders refresh analytics dashboards manually to see current metrics, creating stale data problems. Build a real-time BI dashboard that pushes metric updates via WebSocket as database changes occur, with interactive filtering, drill-down capability, and configurable alert thresholds.

USE CASES IN THE REAL WORLD
----------------------------------------
Operations command centers at Swiggy, Flipkart, and OYO; financial dashboards at banks and payment companies; manufacturing quality control dashboards; and healthcare patient monitoring systems all need real-time metrics with push updates.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
Real-time WebSocket-push dashboards require solving backpressure (don't overwhelm slow clients), efficient database change detection (CDC or polling), selective subscription (client only receives updates for displayed metrics), and connection management at scale — a complete full-stack engineering exercise.

RECRUITER SHORTLIST SIGNAL
----------------------------------------
Real-time data visualization with WebSocket push is a differentiator for full-stack engineers. Companies building internal analytics tools, operations dashboards, and monitoring products look for engineers who can combine data pipelines with interactive frontend visualization. Libraries like D3.js, Recharts, and Apache ECharts are relevant.

ARCHITECTURE & DATA FLOW
----------------------------------------
PostgreSQL trigger or polling service detecting metric changes. Node.js WebSocket server managing subscriptions per metric. React dashboard with Recharts/D3.js for visualization. Client subscribes to specific metric IDs; server pushes updates only for subscribed metrics. Redis pub/sub for broadcasting across multiple WebSocket server instances. Alert threshold configuration with browser notification API.

SCALE & PERFORMANCE TARGETS
----------------------------------------
Push metric updates to 1,000 concurrent dashboard clients within 500ms of underlying data change, with < 100ms client-side chart re-render and zero missed updates under backpressure.

SKILLS COVERED
----------------------------------------
React, TypeScript, WebSockets, PostgreSQL, Node.js, Data Visualization

SCREENER VERIFICATION RUBRIC
----------------------------------------
1. WebSocket push: database metric change reflected on dashboard within 500ms
2. Selective subscription: client only receives updates for charts currently displayed
3. Backpressure handling: slow client receives latest value, not every intermediate value
4. Multi-server: second WebSocket server instance receives same updates via Redis pub/sub
5. Alert notification: browser notification fired when metric crosses configured threshold
