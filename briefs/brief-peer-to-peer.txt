PROJECT BRIEF — Peer-to-Peer File Sharing Network (BitTorrent-like)
======================================================================

Domain    : Distributed Systems
Difficulty: ADVANCED

PROBLEM STATEMENT
----------------------------------------
Centralized file distribution creates single points of failure and bandwidth bottlenecks. Build a peer-to-peer file sharing protocol where files are split into pieces, distributed across peers, and each peer simultaneously downloads and uploads pieces to maximize network throughput.

USE CASES IN THE REAL WORLD
----------------------------------------
BitTorrent protocol powers 40% of internet traffic. IPFS (InterPlanetary File System) uses similar principles for decentralized web. CDN edge cache distribution, software update distribution (Linux packages, game patches), and decentralized storage all use P2P principles.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
P2P networking requires understanding peer discovery (DHT), data integrity (Merkle trees), choking/unchoking algorithms, and concurrent piece downloads — deep networking and distributed systems knowledge. Engineers who have implemented P2P protocols understand distributed coordination at a fundamental level.

RECRUITER SHORTLIST SIGNAL
----------------------------------------
P2P networking knowledge is valued at companies building decentralized systems (Web3, IPFS), CDN infrastructure, and large-scale file distribution. The BitTorrent-like implementation demonstrates complete networking engineering at the protocol design level — rare and impressive to any systems-oriented interviewer.

ARCHITECTURE & DATA FLOW
----------------------------------------
Files chunked into fixed-size pieces with SHA1 hash verification. DHT-based peer discovery or central tracker. TCP connections to multiple peers for parallel piece downloading. Piece selection algorithm (rarest-first). Choking/unchoking algorithm managing upload bandwidth allocation. Merkle tree verification of received pieces.

SCALE & PERFORMANCE TARGETS
----------------------------------------
Achieve > 2x speedup over single-source download for files > 100MB with 5+ peers, maintain 100% data integrity via hash verification, and recover from 2 simultaneous peer disconnections without download failure.

SKILLS COVERED
----------------------------------------
Go, Networking, Distributed Systems, Protocols, Algorithms, Concurrency

SCREENER VERIFICATION RUBRIC
----------------------------------------
1. Speed test: 5-peer download 2x faster than single-source for 1GB test file
2. Integrity verification: corrupted piece detected and re-requested from different peer
3. Peer failure recovery: 2 peers disconnect mid-download, file completes from remaining peers
4. Rarest-first piece selection reduces piece redundancy compared to random selection
5. DHT peer discovery without central tracker server
