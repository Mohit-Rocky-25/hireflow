PROJECT BRIEF — Distributed Workflow Orchestration Engine
======================================================================

Domain    : Distributed Systems
Difficulty: ADVANCED
Est. Time : 30 hours
Tech Stack: Go, PostgreSQL, Kafka, Event Sourcing, Saga Pattern

PROBLEM STATEMENT
----------------------------------------
Business workflows (loan application processing, order fulfillment, video transcoding) involve multiple steps that must execute in order, retry on failure, and checkpoint progress to survive crashes. Build a durable workflow orchestration engine similar to Temporal or Conductor.

USE CASES IN THE REAL WORLD
----------------------------------------
Netflix uses Conductor, Stripe uses Temporal, Uber uses Cadence — all for long-running business process orchestration. In India, Razorpay's payment flows, HDFC's loan processing, and Swiggy's order fulfillment all require durable workflow orchestration.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
Distributed workflows require solving advanced distributed systems problems: exactly-once activity execution, crash-safe checkpointing, deterministic replay, and saga compensation. This is one of the most complex practical distributed systems projects — it demonstrates you can build infrastructure that other engineers rely on.

RECRUITER SHORTLIST SIGNAL
----------------------------------------
Temporal, Cadence, and Conductor knowledge is specifically sought by infrastructure teams at large companies. Engineers who understand durable execution patterns can design systems that don't lose work on failures — invaluable for any company with complex, multi-step business processes.

ARCHITECTURE & DATA FLOW
----------------------------------------
Workflow definitions as Go code with activity steps. PostgreSQL persistence of workflow state via event sourcing. Kafka for worker task distribution. History replayer ensuring deterministic re-execution after crashes. Compensation (saga) logic for rollback on partial failures. REST API for workflow submission and status queries.

SCALE & PERFORMANCE TARGETS
----------------------------------------
Execute 10,000 concurrent workflow instances with guaranteed progress despite worker crashes, and recover interrupted workflows within 30 seconds of worker restart.

SKILLS COVERED
----------------------------------------
Go, PostgreSQL, Kafka, Concurrency, Algorithms, System Design

SCREENER VERIFICATION RUBRIC
----------------------------------------
1. Crash recovery test: kill worker mid-workflow, restart, workflow completes correctly
2. Concurrent execution: 1000 workflows running simultaneously without contention
3. Saga compensation: 5-step workflow failing at step 3 triggers rollback of steps 1-2
4. Exactly-once activity execution: duplicate task delivery produces no double execution
5. REST API for workflow submission, status polling, and cancellation
