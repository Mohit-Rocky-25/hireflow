PROBLEM STATEMENT
----------------------------------------
Multi-tenant APIs frequently experience 'noisy neighbor' spikes and DDoS vectors that degrade service for all tenants simultaneously. Traditional per-instance rate limiting fails in horizontally-scaled clusters because each node has no global state. Build a low-latency, sliding-window and token-bucket distributed rate limiting proxy that intercepts traffic and coordinates token consumption across a Redis cluster with zero race conditions.

USE CASES IN THE REAL WORLD
----------------------------------------
API Gateways at Razorpay, Swiggy, and Flipkart enforce per-customer rate limits across hundreds of servers. Any company offering a public API (SaaS, fintech, e-commerce) needs this. Directly applicable to Cloudflare, AWS API Gateway, and any microservices ingress layer.

ARCHITECTURE & DATA FLOW
----------------------------------------

Supports gRPC streaming and HTTP middleware headers (X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset). Uses Redis WATCH/MULTI/EXEC for optimistic concurrency.
