PROBLEM STATEMENT
----------------------------------------
Building an interpreter from scratch is the ultimate demonstration of computer science fundamentals. Most engineers use programming languages daily but have no idea how parsing, AST construction, scope resolution, or garbage collection work. Build a working interpreter for a custom scripting language with closures, higher-order functions, and a REPL.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
Building an interpreter exercises the deepest computer science knowledge: lexical analysis, recursive descent parsing, scope chain resolution, environment frames, closure capture, and memory management. Engineers who have done this can discuss runtime internals in any language — a massive advantage in senior technical interviews.

ARCHITECTURE & DATA FLOW
----------------------------------------
Lexer (tokenizer) → Pratt parser → Abstract Syntax Tree (AST) → Tree-walking evaluator. Implements: variables, closures, higher-order functions, conditionals, loops, arrays, hash maps, and built-in functions. REPL for interactive evaluation. Error recovery for useful error messages.

SCALE & PERFORMANCE TARGETS
----------------------------------------
Parse and evaluate 10,000-line programs in < 100ms, with correct closure semantics verified by passing 200+ test cases including recursive Fibonacci, higher-order map/filter, and mutual recursion.
