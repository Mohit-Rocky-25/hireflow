PROBLEM STATEMENT
----------------------------------------
Modern applications send notifications across email, SMS, push, WhatsApp, and in-app channels with complex routing logic: preference-based channel selection, deduplication, throttling, and delivery tracking. Build a notification orchestration service that abstracts provider complexity and ensures reliable delivery.

USE CASES IN THE REAL WORLD
----------------------------------------
Every consumer app in India sends notifications — Swiggy, Zomato, PhonePe, HDFC Bank. WhatsApp Business API, FCM, and SMS providers (Twilio, MSG91) all need orchestration. This is core infrastructure at scale.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
Notification systems have complex requirements: idempotency (don't send the same notification twice), user preference routing (send to email if push disabled), rate limiting per channel, retry logic, and delivery analytics. Building this end-to-end demonstrates production-grade distributed systems thinking.

ARCHITECTURE & DATA FLOW
----------------------------------------
Node.js orchestrator receiving notification requests from internal services via Kafka. User preference resolver selecting optimal channel. Provider plugins (FCM, Twilio SMS, WhatsApp Business API, SMTP). Redis deduplication using event fingerprints. PostgreSQL delivery audit log. Retry queue with exponential backoff.
