PROBLEM STATEMENT
----------------------------------------
Traditional mutable database applications lose the history of how data changed, making debugging, auditing, and time-travel queries impossible. Build an Event Sourcing framework where all state changes are stored as immutable events, and current state is derived by replaying the event log.

USE CASES IN THE REAL WORLD
----------------------------------------
Financial audit trails (every transaction history preserved), legal compliance (immutable evidence of who changed what when), version control systems, and domain-driven design applications. Martin Fowler's event sourcing pattern is used at Uber, Netflix, and any application requiring complete audit history.

WHY THIS IS HARD (COMPETENCY REDUCER)
----------------------------------------
Event sourcing requires understanding aggregate pattern, event streams, projection rebuilding, temporal queries, and the CQRS (Command Query Responsibility Segregation) pattern. These are advanced DDD concepts that senior backend engineers are expected to know and apply in complex domain-driven systems.

RECRUITER SHORTLIST SIGNAL
----------------------------------------
Domain-Driven Design, CQRS, and Event Sourcing are explicitly required in senior backend roles at enterprise software companies. Zoho, Freshworks, and any company building complex B2B products with audit requirements value engineers who can design event-sourced systems. Shows architectural thinking beyond CRUD.

ARCHITECTURE & DATA FLOW
----------------------------------------
Event store in PostgreSQL with append-only event table. Aggregate loading via event replay from store. Projections computing read models from event streams asynchronously. Kafka for event distribution to multiple projection workers. Snapshot mechanism for performance on long event streams. Time-travel query API for historical state retrieval.

SCALE & PERFORMANCE TARGETS
----------------------------------------
Rebuild complete application state from 1M events in < 30 seconds, snapshot aggregates with > 500 events for instant loading, and serve time-travel queries returning state at any past timestamp.

SCREENER VERIFICATION RUBRIC
----------------------------------------

3. Snapshot optimization: aggregate with 1000 events loads in < 10ms via snapshot
4. Concurrent write test: two commands on same aggregate handle optimistic concurrency
5. Event schema evolution: old events deserialize correctly with new schema version
